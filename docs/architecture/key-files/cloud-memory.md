# Key files: HydraDB cloud memory

[Subsystem index](../KEY_FILES.md). Current behavior and invariants.

- `src/core/hydradb.ts`, `src/core/search/hydra-primary.ts`, `hydra-filters.ts` — opt-in HydraDB client and primary relevance ranking. Both public hybrid entry points and keyless recall consult the cloud backend before local embedding capability. Search metadata names `backend: hydradb`; operations preserve that order instead of running local fanout, fact-ranking additions or escalation. Source and live read policy remain local authorization checks; type/date/slug filters and offsets do not switch backends. Unknown cloud pages have unknown trust, cannot pass a trust floor or proactive suppression, and never acquire a local fetch id. Explicit keyword enumeration, image embeddings and structural symbol walks retain their local contracts.
- `src/core/hydradb-mirror.ts`, `hydradb-transfer.ts` — serialized write-through and cursor catch-up. Page identity includes source, slug and microsecond update time; old cursors replay once. Full-body projection and title redaction happen before ingestion. Per-item queue acceptance and asynchronous indexing must succeed before the cursor advances; delete failures retain the deletion cursor. The background drainer tracks pending key checks and bounds shutdown waits. The optional live smoke only creates and deletes synthetic databases.
